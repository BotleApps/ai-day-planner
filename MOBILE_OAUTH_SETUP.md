# Mobile OAuth Setup — Step-by-step

You're getting the Google Cloud OAuth client IDs. This file lists what to do
with each one, so the native shells can authenticate.

There are **three** OAuth clients to create in Google Cloud Console
(APIs & Services → Credentials → Create credentials → OAuth client ID).
All three share the same Google project and OAuth consent screen.

---

## 1. Web OAuth client (you may already have this)

- **Type:** Web application
- **Authorized redirect URIs:**
  - `https://<your-cf-app>.cfapps.eu12.hana.ondemand.com/api/auth/callback/google`
  - (any other deployed environments)
  - For local dev: `http://localhost:3000/api/auth/callback/google`

**Env vars to set:**

```env
GOOGLE_CLIENT_ID=<web-client-id>.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=<web-client-secret>
NEXT_PUBLIC_GOOGLE_WEB_CLIENT_ID=<web-client-id>.apps.googleusercontent.com
```

`NEXT_PUBLIC_GOOGLE_WEB_CLIENT_ID` MUST be set at **web build time** — it's
baked into the JS bundle and used as the `serverClientId` on Android so the
native sign-in mints an ID token whose `aud` matches the web client.

---

## 2. iOS OAuth client

- **Type:** iOS
- **Bundle ID:** `com.sortedplan.app`  (must exactly match `capacitor.config.ts`)

Google returns two values you need:
- `iOS client ID` — looks like `123456789-abc.apps.googleusercontent.com`
- `iOS URL scheme` — the **reversed** client ID, like `com.googleusercontent.apps.123456789-abc`

### Wire it up

**(a)** Set env vars:

```env
GOOGLE_IOS_CLIENT_ID=<ios-client-id>.apps.googleusercontent.com
NEXT_PUBLIC_GOOGLE_IOS_CLIENT_ID=<ios-client-id>.apps.googleusercontent.com
```

**(b)** Update `ios/App/App/Info.plist` — replace the placeholder I added:

```xml
<key>CFBundleURLTypes</key>
<array>
    <dict>
        <key>CFBundleURLSchemes</key>
        <array>
            <string>REPLACE_WITH_REVERSED_IOS_CLIENT_ID</string>   <!-- e.g. com.googleusercontent.apps.123456789-abc -->
        </array>
    </dict>
</array>
```

Or run the helper script (does the substitution for you):

```bash
./scripts/wire-ios-oauth.sh com.googleusercontent.apps.123456789-abc
```

**(c)** Resync:

```bash
npx cap sync ios
```

## 3. Android OAuth client

- **Type:** Android
- **Package name:** `com.sortedplan.app`
- **SHA-1 certificate fingerprint:** REQUIRED — you must register the SHA-1 of
  every keystore that will sign the app:
  - your **debug keystore** (for local dev / emulator runs)
  - your **release/upload keystore** (for Play Store)
  - the **Google Play app-signing key** if you let Play sign on your behalf

### Getting the debug keystore SHA-1

```bash
keytool -list -v \
  -keystore ~/.android/debug.keystore \
  -alias androiddebugkey \
  -storepass android -keypass android | grep SHA1
```

The debug keystore is auto-generated by Android Studio on first run. If it
doesn't exist yet, run any Android Studio project once to create it, or:

```bash
mkdir -p ~/.android
keytool -genkey -v -keystore ~/.android/debug.keystore \
  -alias androiddebugkey -keyalg RSA -keysize 2048 -validity 10000 \
  -storepass android -keypass android \
  -dname "CN=Android Debug,O=Android,C=US"
```

### Getting your release/upload keystore SHA-1

```bash
keytool -list -v -keystore <path-to-your-release.keystore> \
  -alias <your-alias> | grep SHA1
```

### Getting the Play app-signing SHA-1 (when ready to publish)

Play Console → your app → Setup → App signing → "App signing key certificate"
SHA-1 fingerprint. Add it to the Android OAuth client in Google Cloud Console.

### Env var

```env
GOOGLE_ANDROID_CLIENT_ID=<android-client-id>.apps.googleusercontent.com
```

> No `NEXT_PUBLIC_GOOGLE_ANDROID_CLIENT_ID` is needed — Android uses the **web**
> client ID as its `serverClientId` (so `aud` matches the web token audience).

> No URL scheme is needed on Android — Google Credential Manager / GIS handle
> the OAuth flow without URL schemes.

## 4. Scaffold the Android platform (run once)

After you have the OAuth client IDs above, scaffold the Android project. This
creates the `android/` folder Capacitor needs:

> **Disk note:** `npm install` for this project needs ~1.5 GB free. If you're
> tight, `npm cache clean --force` reclaims `~/.npm` (currently ~10 GB on this
> machine) but slows down subsequent `npm install` invocations until the cache
> rebuilds.

```bash
# Set this to the deployed URL the native shell will load
export CAP_SERVER_URL="https://<your-cf-app>.cfapps.eu12.hana.ondemand.com"

# Or, for local dev against your machine:
# export CAP_SERVER_URL="http://10.0.2.2:3000"

# Install deps if you haven't
npm install

# Scaffold Android
npm run cap:add:android

# Sync (writes the CAP_SERVER_URL into the native config)
npx cap sync android
```

Commit the `android/` folder to git (same as `ios/` already is).

---

## 5. Backend env (CF / dev / qual / prod)

Update each environment's secrets with the three audience values so server-side
token verification accepts all three platforms:

```bash
cf set-env <app> GOOGLE_CLIENT_ID         "<web-client-id>.apps.googleusercontent.com"
cf set-env <app> GOOGLE_CLIENT_SECRET     "<web-secret>"
cf set-env <app> GOOGLE_IOS_CLIENT_ID     "<ios-client-id>.apps.googleusercontent.com"
cf set-env <app> GOOGLE_ANDROID_CLIENT_ID "<android-client-id>.apps.googleusercontent.com"
cf restage <app>
```

`lib/verify-google-token.ts` already reads all three and accepts a token whose
`aud` matches any one of them.

For local dev, set them in your `.env.local`.

---

## 6. Run it

```bash
# iOS simulator
npm run mobile:ios

# Android emulator
npm run mobile:android
```

`scripts/run-mobile.sh` boots `npm run dev`, points the native shell at the
correct host alias for the platform, scaffolds the platform if missing, and
launches the simulator/emulator.

---

## 7. Smoke-test the sign-in flow

1. App boots → loads your deployed web app.
2. Tap "Sign in with Google".
3. Native Google account picker appears (NOT a WebView with OAuth — that's the
   old broken path).
4. Pick an account.
5. The app exchanges the ID token with `/api/auth/callback/credentials/google-native`.
6. You land on the home page logged in.

If you see "disallowed_useragent" or a WebView with the Google sign-in page,
the native plugin isn't being detected. Check:

- `Capacitor.isNativePlatform()` returns `true` in the running app
  (`lib/use-is-native.ts` exposes a hook for this)
- The `google-native` provider is registered in `auth.ts` (it is)
- `NEXT_PUBLIC_GOOGLE_IOS_CLIENT_ID` / `NEXT_PUBLIC_GOOGLE_WEB_CLIENT_ID` are
  set **at the time the web app was built** and deployed
- For iOS: the `CFBundleURLTypes` reversed client ID is correct (no
  `REPLACE_WITH_…` placeholder)
- For Android: the SHA-1 of the keystore signing the running APK is
  registered in the Android OAuth client

## Troubleshooting reference

| Symptom | Likely cause | Fix |
|---|---|---|
| iOS: app opens, Google sign-in spinner forever | Reversed client ID still placeholder | Update `Info.plist`, `npx cap sync ios`, rebuild |
| iOS: "developer_error" | Bundle ID mismatch | Verify `com.sortedplan.app` in Xcode → General → Bundle Identifier |
| Android: `DEVELOPER_ERROR` (code 10) | Wrong SHA-1 registered | Add SHA-1 of the keystore signing the APK that's running |
| Android: "ID token audience mismatch" on server | `serverClientId` ≠ web client ID | Confirm `NEXT_PUBLIC_GOOGLE_WEB_CLIENT_ID` is set at build time |
| Server logs "FATAL: No Google OAuth client IDs configured" | No env vars set | `cf set-env` the three client IDs |
| App loads but no API works | `CAP_SERVER_URL` set to localhost in prod build | Resync with the deployed HTTPS URL |
